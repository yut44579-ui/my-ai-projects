# 去掉出处 + 不再答非所问 + 不再小事转人工

> 用户的三条反馈：
> ① ai 会乱答
> ② 还是会乱接入人工，不要一点小事情就人工
> ③ **不要标明出处，来源泄露信息**

---

## D96 ★★★ 出处是**内部信息**，不能给客户看

**用户的要求**：「不要标明出处，来源泄露信息」。

**★ 为什么这不是"少显示一行字"的小事**：
```
那些"出处"是**内部文档名**：
  《报价底线》《客户分级标准》《售后服务承诺》《费用报销管理办法》
                        ↑ 光看名字就能猜出这家公司有哪些内部制度
→ 对一个**外部客户**来说，这就是在泄露内部信息
→ 而且客户看到"出处"会以为我们在念文档，反而显得不专业
```

**★★ 但"可溯源"这条纪律并没有破** —— 这是关键：
```
给客户看的  →  只有答案，没有任何来源标注
给自己人看的 →  控制台「试一句」和人工工作台**单独一栏**显示出处
              （客服要核对 AI 说得对不对，必须看得到）
qa_log      →  citations 照样存着，出事能查
```
> **溯源是内部的事，不是给客户的交付物。**

### 三处泄漏点，全部堵上

```
① 提示词        原来明确要求"最后另起一行写〔出处：《文件名》〕" → 改成明确禁止
② 出站检查      加 strip_citations() 兜底 —— 提示词说了模型不一定听
③ 原文直出降级   原来写了《文件名》→ 降级的时候把内部文档结构全抖出去了
④ 挂件前端      原来把出处渲染成一行小字 → 删掉，并再兜一层
```

**出站检查的兜底规则**（模型不听话时用）：
```python
CITATION_PATTERNS = [
    r"[〔\[（(]?\s*出处\s*[:：][^〕\]）)\n]*[〕\]）)]?",
    r"[〔\[（(]?\s*来源\s*[:：][^〕\]）)\n]*[〕\]）)]?",
    r"根据\s*《[^》]{1,40}》[，,]?\s*",
    r"《[^》]{1,40}》\s*(?:第[\d.]+条|规定|里|中|写明|写的)",
]
```
★ 只删"标注"，不删正常内容 ——
  测试确认「我们有三条产品线：汽车零部件、医疗器械零件、半导体设备件」原样保留。

**实测：16 句里出处泄露 0 处** ✅

## D97 ★★★ 「短」不等于「没意义」

**现象**：用户问「**你是谁**」，AI 回"没太确定你想问什么"。

**原因**：
```python
NONSENSE 里有一条  r"^[\u4e00-\u9fa5]{2,3}$"   # 两三个字的孤立词
"你是谁" 只有 3 个字 → 被判成"看不出想干什么"
```
**★ 但"你是谁""在吗""多少钱"都很短，意思却很清楚。**

**修法**：`is_nonsense` 里**先看它是不是能识别的问句**，是的话就不是无意义。
```python
for _cat, pats in SIMPLE.items():
    if _match(pats, t):
        return False     # ← 能识别的问句，再短也不是无意义
```

## D98 ★★ 「你这个系统是干什么的」被转人工 —— 这就是"一点小事就人工"

**现象**：队列里躺着一条
```
"你这个系统是干什么的"  →  模型判定资料不足以回答  →  转人工
```

**原因**：
```python
r"(你|您).{0,3}(是|做|干).{0,3}(什么|啥|嘛)"
              ↑ 中间只允许跳过 3 个字
"你这个系统是干什么的"  →  "这个系统"是 4 个字 → 匹配不上
→ 落进检索 → 资料里当然没有"我们这个系统是干什么的"
→ 模型说"资料不足以回答" → 转人工
```

**★ 这是个特别典型的"一点小事就人工"**：
```
用户问的是"你是什么" —— 答案是我们自己定义好的，根本不用查资料
结果它去查了资料、查不到、然后甩给人
```

**修法**：把跳过长度从 3 放宽到 8，并补上「这个系统 / 这个软件 / 这个平台」这一族说法。

## D99 ★★★ 用脚本改正则，`\n` 变成了字面量，整行被注释吞掉

**现象**：明明加了"两三个字算无意义"的规则，但「怎么用」还是不走澄清。

**原因**：
```python
# 我用 PowerShell 加规则时，替换字符串里的 `\n` 没被解释成换行，
# 而是变成了**字面的反斜杠 n**：
r"^[a-z]{1,6}$",    # 纯字母乱敲\n    # ★ 两个字...\n    r"^[\u4e00-\u9fa5]{2,4}$",
                    ↑ 整行还在第一行的注释里 → 后面的规则**全被注释掉了**
```

**★ 这个坑最气人的地方**：
```
· 脚本报"已加成功" ✅
· 文件里 grep 得到那行文字 ✅
· 但它是**注释的一部分**，规则根本没生效 ❌
```

**★ 教训**：
> **往代码里插代码，不要用字符串拼接。**
> 用 `edit` 工具，或者写清楚的多行模板。
> 字符串里的转义（`\n`、引号、缩进）在一个层里对、在另一个层里就错了。

**附带教训**：脚本报"成功"只说明"它把字符串写进去了"，
**不说明"那段代码有作用"**。改完必须**独立验证行为**。

## D100 ★★ 判断顺序里，`is_nonsense` 和 `is_simple` 会互相打架

这一轮暴露的顺序问题（都实测踩过）：

```
① is_nonsense 排最前，但它的"短词"规则会吃掉「你是谁」「怎么用」
   → 修法：is_nonsense 内部先排除能被 SIMPLE 识别的
② 软风险必须排在硬风险前面
   （"怎么报价"会被"报价"这个宽泛规则吃掉）
③ `quality is None`（还没检索）必须排在质量分档前面
   （否则所有要查资料的问题都在检索之前被拦下）
```

**★ 一句话总结**：
> **具体规则排在宽泛规则前面；"能识别的"排在"识别不了的"前面。**
