# 实时监控 + 分屏互不干预

> 用户的原话：
> 「要互不干预的，也就是说我在模拟官网右下角的 AI 客服，
>   分开页面也就是我在官网进入控制台或者人工那些，是另起一页观察，
>   这样才会测试聊天记录，以及更为准确的知道 AI 做了什么」

---

## D82 ★★ 只在同一个标签页里跳转，等于把"观察"这件事做废了

**现象**：模拟官网顶部有个「打开控制台」的入口，
但点它会在**同一个标签页跳走** —— 官网的聊天窗口关掉了，
刚才那个会话的上下文也就断了。

**★ 后果不只是"不方便"，而是**：
```
用户想做的事是「一边在官网问，一边看 AI 怎么处理」
同标签页跳转 → 只能二选一 → 根本没法观察
```

**修法**：`target="_blank" rel="noopener"`.

**★ 这条的普遍意义**：
> **"观察"这个需求，需要两个东西同时可见。**
> 任何会让"被观察的对象"消失的设计，都等于没做观察功能。

---

## D83 ★★★ 人工队列 ≠ 实时监控

**用户要的是**：「随时知道用户在说什么，避免不知道导致损失」。

**第一版我打算让他去人工队列里看 —— 但那是错的**：
```
人工队列只显示**已经转人工**的那部分
但真正需要被看见的，还包括**AI 正在自动回答的那些**
```

**★ 因为出事通常不是转人工时出的**：
```
转人工    → 有个人在看，不会有损失
AI 自动发 → 那句话已经到客户手机上了，没人拦得住
```

**所以 `/api/live` 给的是全部活跃会话**，并在界面上把这一条写清楚。

### 实时页显示什么

```
顶部数字：活跃会话 / 收到问题 / AI 自动答了 / 转了人工 / 等人处理
（★ 五个数字里最关键的是「AI 自动答了」—— 那是没人经手的）

每个会话：
  web-gcp85v8h  [等人工]  web · 问了 3 次 · 自动 2 / 转人工 1   10:39:51
    │ 有哪些资质认证
    │   IATF 16949、ISO 9001、ISO 13485…〔出处：《资质认证》〕
    │   AI 自动发出 · 检索质量 0.9
    │ 最小起订量多少
    │   打样阶段 1 件起做，不限最低数量…〔出处：《交期与起订量》〕
    │   AI 自动发出 · 检索质量 0.9
    │ 你们能便宜点吗
    │   这个我答不了，我让人来回你。
    │   转人工（没发给客户）· 检索质量 0 · should_escalate
```

**★ 关键信息都在**：
- 访客 id（对得上官网那边是谁）
- 每一轮：问了什么、AI 答了什么、**发没发出去**、检索质量、判断依据
- 会话状态：AI 在答 / 刚转人工 / 等人工

**自动刷新 5 秒**（可关）。
