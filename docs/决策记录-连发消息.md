# 连发多条消息怎么处理

> 用户的问题：「如果用户连续多次发消息，要怎么及时处理多个消息呢」

---

## 先查现状（不猜）

用真实接口试了「客户连发 3 条」：

```
客户: 我想问一下        → AI 答「没太确定你想问什么…」   ← ★ 抢答半句话
客户: 关于报价的事      → 转人工（队列里记的是这句）
客户: 你们能便宜点吗    → 静默（真正的问题被吞了）
```

**★ 两个真问题**：

```
① AI 抢答半句话
   客户才打了 6 个字，AI 就下结论说"没太确定你想问什么" ——
   他话还没说完。

② ★ 客服拿到的是半截需求
   队列项写「关于报价的事」，但客户真正想问的是「你们能便宜点吗」。
   ★ 这个比第 ① 个严重：客服按半截需求准备，回头客户说"我问的是能不能便宜"，
     两边对不上，白跑一趟。
```

（顺带确认了一件好事：队列**没有被刷爆** —— 一个会话只产生一条待处理。
  这个靠的是之前做的"有人工在管就静默"。）

---

## D124 ★★ 防抖合并：等一小会儿，把连发的几条并成一条

**做法**：worker 取出消息后、处理之前，等一个小窗口（默认 2.5 秒）。
窗口期内同一会话又来消息，就**合并成一条**再处理。

```python
msg = _debounce_merge(msg, channel)   # 等 2.5s，把连发的并进来
_process(msg, channel)
```

**★ 为什么放在 worker 里，不放在 accept 里**：
```
accept 必须**立刻返回** —— 平台在等 200 响应，不能拿它跑模型/等待。
放到 worker 里不影响响应；而且 worker 是单线程，天然串行不会乱序。
```

**★ 窗口取 2.5 秒**：
```
太短 → 客户打字慢的时候还是会被拆开
太长 → 每个人都觉得"怎么半天不回"
2.5 秒比大多数人打字间隔长，又短到不觉得卡。
★ 可配（DEBOUNCE_SECONDS），设成 0 就恢复"立即回答"。
```

**★ 合并上限 6 条**：防止有人刷屏拼出一条超长消息。

**实测**：
```
改前  客户收到 2 条：澄清 + 转人工
      队列记「关于报价的事」
改后  客户收到 1 条：直接转人工
      队列记「我想问一下 / 关于报价的事 / 你们能便宜点吗」
```

## D125 ★★ 合并 ≠ 去重（这两件事很容易混）

**改这个的时候，smoke8 有两条失败的**：

```
smoke8 第 2 组：「网页渠道不能去重」
  它连发两条**一模一样**的话，断言"两条都被处理了 = 发件箱里有 2 条"
  → 加了防抖合并之后，两条被并成一条 → 断言不成立
```

**★ 关键区别**（我想清楚之后才动的测试）：
```
去重（duplicate）= 第二条被**丢掉**，用户的话没了     ← 不能这样
合并（merge）    = 两条一起处理，用户的话都在        ← 现在这样
```

**★ 所以测试的原意是对的，断言写错了**：
```
它真正要验的是"第二条没被丢掉"，不是"必须产生两条回答"。
→ 改成断言：① 第二条判定不是 duplicate ② 两条内容都进去了
```
★ 这不是"改测试让它通过" —— 是原来的断言**把两件不同的事当成了同一件**。

**★ 顺带想清楚的一个行为**：用户重复问同一句，通常是**没等到回答**（着急了）。
  合并答一次正是他要的；反过来给他两条一样的回答，只会让他更烦。

## D126 ★ 客户在人工接管期间又说话 —— 队列上看不见

**用户的第二个问题**："怎么**及时**处理多个消息"。

```
场景：客服接管了，正在看这个客户的会话；
      客户又连发两句 —— 但队列里那条看起来**一点变化都没有**。
→ 客服不知道有新内容，会一直停在原来的判断上。
```

**做法**：给 `handover_queue` 加两个字段
```
new_count     接管/建单之后客户又发了几条
last_user_at  客户最后说话的时间
```
静默时累加，**客服一看会话就清零**。

**★ 为什么是"一看就清零"而不是"已读按钮"**：
```
多一个动作，就多一次忘记。
客服点开这条会话本来就是他"看了"的证明，不用再让他确认一次。
```

**界面上**：
```
左列：能报个价吗
      web-9pp8ae6f · 15:28 · 直接转人工 · ● 又说了 2 句
详情：● 你接管之后客户又说了 2 句，往下翻看最新的
```

## D127 ★ 中文引号又炸了（第 N 次）—— 加护栏

改 config 的时候，注释里写了 `"我想问一下" / "关于报价的事"`，
**在 Python 双引号字符串里用了全角引号** → SyntaxError。

**这个坑在这个项目里踩了至少 5 次**（每次都是中文注释/文案里带引号）。
所以这次除了修，还在 smoke9 里加了一条护栏：

```
扫描所有 .py 文件，找"字符串字面量里出现全角引号"的行并报错
```

★ 教训：**反复踩同一个坑，就该把它变成一条自动检查**，
  而不是每次都靠"下次注意"。
