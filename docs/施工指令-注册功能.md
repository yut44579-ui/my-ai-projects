## 一、后端（新增本地账号，别动既有端点语义）

1. **账号存储** `state/accounts.json`（走既有 Repository 抽象，别绕过）
```
{ "username": "...", "display_name": "...",
  "pwd_algo": "pbkdf2_sha256", "pwd_salt": "...", "pwd_hash": "...", "pwd_iterations": N,
  "created_at": "...", "last_login_at": "..." }
```
2. **密码必须哈希（绝不明文）**：用标准库 `hashlib.pbkdf2_hmac`（**不引新依赖**），
   每账号独立随机 salt（`secrets.token_bytes`），迭代次数写进记录便于将来升级
3. **新增端点**：
   - `POST /api/auth/register` `{username, password, display_name?}`
     · 校验：账号 2~40 字符（允许中文/字母/数字/下划线/点/中划线）、密码 ≥6 位
     · **账号重复 → 409** + 人话「这个账号已被注册」
     · 成功 → 返回账号信息（**绝不返回 salt/hash**）
   - `POST /api/auth/login` `{username, password}`
     · 成功 → 返回账号信息（display_name 等）；同时更新 `last_login_at`
     · 失败 → **401** + 人话「账号或密码不对」
       → **不区分"账号不存在"和"密码错"**（安全习惯，别给撞库提示）
   - `GET /api/auth/accounts/exists?username=...`（注册页即时重复检测用，返回 `{exists: bool}`）
4. **首次使用引导**：若系统里**一个账号都没有**，登录页给出明显引导「先注册一个」
   （「游客进入」这条后路仍保留）

6. **退出登录**：清本地会话 → 回登录页
7. **「忘记密码？」**：本地模式下的**诚实**做法（二选一并在报告说明理由）：
