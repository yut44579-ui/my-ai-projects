## D58 ★★★ 用正则去改 nginx 配置，把整站搞挂了

**现象**：
```
我用正则想在配置里"删掉旧块再加新块" → 正则没匹配上（静默失败）
→ 又插了一份 → duplicate location → nginx -t 失败
→ nginx 没起来 → **作品集 / AI供应链 / 销售Agent 全部 000**
```

**★ 这条最该记的不是"正则写错了"，而是两个更深的东西**：

**① 正则替换失败时是静默的。**
```
找到就替换，找不到就当没这回事 —— 而调用方完全不知道。
"什么都没删"和"删成功了"返回值一样。
```
凡是"改配置"的操作，都必须**先确认改成功了**（比对长度/标记数），
不能假定替换生效。

**② 配置这种东西应该整份重写，而不是局部修补。**
局部修补的复杂度（找锚点、处理缩进、保证幂等、失败回滚）
远高于**整份重写** —— 而整份重写的结果是确定的、可校验的。

**修法**：直接写一份完整配置覆盖。
```python
CONF = r"""...完整的 nginx 配置..."""
```
**代价**：配置变长了，改一处要改整份。
**收益**：任何时刻的配置都是**确定的**，不会因为"上次删了一半"变成脏的。

**★ 附带教训**：我改生产配置之前**没有先备份**。
这次运气好（坏的还在 /tmp 里能查），但当时手上没有回滚点。
**动线上配置前的第一件事应该是备份。**

## D59 ★★ 子路径部署：前缀必须加在封装里，不能加在调用处

**现象**：界面在 `/demo/kefu/` 下所有接口 404。

**原因**：界面里写的是绝对路径 `fetch('/api/...')`，
在子路径下会被解析成 `http://host:8081/api/...` → 404。
（和销售 Agent 踩的是同一个坑。）

**修法**：运行期算前缀。
```js
window.__BASE__ = new URL('.', location.href).pathname.replace(/\/$/, '');
const API = (p) => window.__BASE__ + p;
```

**★★ 但我第一次改错了，而且"看起来成功了"**：
```
我去替换调用处的 `fetch('/api…`
→ 一个都没匹配上（真正的 fetch 在 api() 封装里，参数是变量 p）
→ 脚本却报告"替换了 1 处"（那处其实在我自己的注释里）
→ 我以为改好了，重新部署 → 还是 404
```

**教训**：
> **补丁脚本自己报"成功"，不等于补丁生效了。**
> 必须**独立验证结果**（我用 grep 数了一下实际带前缀的 fetch 有几个，
> 才发现真正的那个没改）。

## D60 ★★ 字符串替换 `fetch('/api' → `fetch(API('/api' 弄坏了括号

**现象**：`SyntaxError: missing ) after argument list`，整个界面白屏。

**原因**：朴素替换不补右括号。
```js
原：  fetch('/api/web/chat', {...})
改后：fetch(API('/api/web/chat', {...})   ← 少一个 )
```

**★ 这类错误是"静默的"**：替换脚本不会报错，页面也不报错给你看 ——
只有在浏览器里才会看到白屏。

**修法**：加了一个**界面 JS 语法检查器**（`scripts/check_js_syntax.mjs`），
把每个 `<script>` 块抽出来用 `new Function()` 试解析。
**这个检查器一眼就抓到了那个括号错误。**

★ 补丁脚本 + 独立验证，是这次唯一有效的组合。

## D61 ★★ 手机窄屏：面板左边溢出屏幕

**现象**：手机上聊天面板左边被切掉一块。

**原因**：面板固定 `width:372px` + `right:24px`，
在 375px 的屏上 `372 + 24 > 375` → **从左边溢出 21px**。

**修法**：窄屏媒体查询改成"左右各留 8px、宽度自适应"。

**★ 这个问题在桌面浏览器上永远看不出来** —— 必须用手机视口量。

## D62 ★★★ 轮询竞态：同一条回答出现了 6 遍

**现象**：手机上同一条回答重复出现 6 次。

**排查过程**（值得记）：
```
先查后端 → web_outbox 里每个会话**只有 1 条** → 后端没问题
→ 那就一定是前端：多个轮询在并发
```

**原因**：
```
poll() 每 1.2 秒一次，但一次 poll 要**两个往返**
（拉消息 + 限流检查）→ 网络一慢就超过 1.2 秒
→ 多个 poll 并发在飞 → 都读同一个还没更新的 since
→ 同一条消息被 add 多次
```

**修法**：
1. 加并发闸 `pollBusy`，任何时刻只允许一个 poll 在跑
2. 把限流检查拆出去，单独走 10 秒一次的定时器

**★ 教训**：
> **"定时器 + 异步" 必然有竞态，除非显式加闸。**
> 而且它的表现形式（重复内容）看起来像"后端返回了重复数据"，
> **会把你引向错误的排查方向** —— 我先查了后端，白查一轮。
