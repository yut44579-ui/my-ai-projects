## 4. 当前 API（12 个）
```
GET  /api/health                     健康 + 数据快照 + 代码版本
POST /api/upload                     上传 xlsx/csv → file_id / rows / columns / sha256
GET  /api/schema                     数据字典
POST /api/execute                    执行：算数 + 渲染（临时路径）
GET  /api/download/{execution_id}    下载真实 xlsx
GET  /api/executions                 执行记录列表
POST /api/tasks                      创建任务（含冻结 Spec）
GET  /api/tasks                      任务列表
GET  /api/tasks/{task_id}            单任务（含完整 Spec）
POST /api/tasks/{task_id}/run        按冻结 Spec 执行一次
GET  /api/tasks/{task_id}/runs       该任务执行历史
（+ 静态挂载 / 指向 web/）
```
**缺口**：无"自然语言分析"、无客户/产品/区域维度分析、无异常检测、无行动计划、无周报、无权限、无黑白名单、无熔断。

## 5. 当前数据库结构
**无数据库**。JSON 落盘：
- `state/uploads.json`：file_id / 文件名 / 行数 / 列 / 大小 / sha256 / stored_path / 时间
- `state/tasks.json`：task_id / name / file_id / spec（冻结）/ status / created_at
- `state/executions.json`：execution_id / task_id / 状态 / 金额 / 行数 / 数据 SHA256 / 代码版本 / 耗时 / 产出路径 / 错误
（原子写 + 进程内锁）

## 8. 必须修改的部分
1. **存储**：JSON → **需要真正的数据库**（行动计划要 CRUD、权限要用户表）—— 建议 SQLite（轻量）或 MySQL（用户此前偏好 MySQL）
2. **auth/权限**：目前**无任何登录与权限**，需要新增（文档第十三节要求后端强制）
3. **Word/PDF 解析**：需新装 python-docx / pypdf（或 PyMuPDF）
4. **自然语言入口**：需要接 LLM（当前**完全没接**，TASK-005 AI Parser 未做）
5. **前端**：从"五区块功能页"→"**左侧导航 + 中间工作区 + 右侧 AI 结论**"的企业级布局（深色）
6. **配置外置**：目前路径/端口硬编码在代码里

## 9. 潜在风险
| 风险 | 说明 | 应对 |
|---|---|---|
| **口径漂移** | 新分析维度（客户/产品/区域）若各自实现筛选，容易与 D16 不一致 | 一律走 `metrics.py` 的同一口径 |
| **LLM 编数字** | 文档第八/十一节要求严格区分"事实/推断" | 数字全部程序算，LLM **只**组织语言；输出强制分区【发生了什么】=数据、【为什么】=推断 |
| **无权限=裸奔** | 现在任何请求都能调 API | 权限必须在后端；先做最小 RBAC |
| **JSON 落盘并发** | 多用户/并发写会冲突 | 迁数据库时一并解决 |
| **UI 重写风险** | 文档第十九节第 10 条禁止"为 UI 重写后端" | 前端重做，后端**只加不改**（现有 12 端点保持兼容） |
| **Word/PDF 解析质量** | 复杂文档提取易失真 | 第一阶段只做"文本提取 + 摘要"，不上 RAG |

## 10. 推荐的最小迁移方案
```
阶段 A（不动后端）：前端深色企业级骨架 + 复用现有 12 端点
   → TASK-002 骨架 → TASK-003 迁移上传 → TASK-004 自然语言入口（先接 LLM，只做"理解问题→映射到已有指标"）

阶段 B（扩分析，复用 metrics/executor）：TASK-005 销售分析（含日趋势）→ 006 客户分析 → 007 产品分析 → 008 异常发现

阶段 C（新能力）：TASK-009 行动计划（先 SQLite 表）→ 010 周报（复用 renderer 出 Excel + 页面）

阶段 D（安全）：TASK-011 权限 → 012 黑白名单 → 013 熔断降级 → 014 操作日志

阶段 E：TASK-015 整体验收
```
**关键原则**：现有 12 个端点**保持向后兼容**；新能力**只加端点**，不改既有语义；
所有数字仍由 `metrics.py`/`executor.py` 计算；LLM 只负责理解与组织语言。
