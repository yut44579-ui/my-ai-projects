# 拆成两个页面：客服台 / 技术后台

> 用户的反馈：
> 「不是在这样页面弄技术处理问题的啊，我的意思重新弄一个关于技术的页面那种懂嘛」

---

## D103 ★★★ 「谁能看到什么」本身就是产品设计

**用户说的是"重新弄一个技术页面"，但背后是一个更重要的判断**：

```
原来的控制台把两类人混在一起：
  客服/销售 需要：实时、试一句、人工、报问题
  技术      需要：问题处理台、知识库、渠道、模型、学习、治理

混在一起的后果：
  · 客服看到「模型」「治理」「渠道」会懵 —— 他不知道那些是什么，
    也不敢点（怕点坏了）
  · 技术要在一堆业务页里翻到「问题」标签，每次多两步
  · 而且**权限上也说不通**：治理里的急停、模型配置，
    不该让一个只会回话术的客服随手碰到
```

### 拆法

```
index.html   客服台     实时 / 试一句 / 人工 / 我的问题
dev.html     技术后台   问题处理台 / 知识库 / 渠道 / 模型 / 学习 / 治理
```

**★ 两边都有「问题」，但看到的东西完全不同**（这是关键）：
```
客服看「我的问题」  → 填个名字，看我报的每一条处理到哪一步了
                     技术说修好了 → 这里出现"你去试试，好了吗？"
                     点「好了」关闭 / 点「还没好」打回
技术看「问题处理台」→ 干活的地方：接手、看自动附的现场、填方案、提交
```

**★ 客服侧不显示"报个问题"以外的技术动作**：
```
· 不显示「问题处理台」（那是技术干活的界面）
· 技术侧不显示右下角那个红色「报个问题」按钮
  —— 他们是**处理问题的人**，不是报问题的人
· 技术侧不显示"我报的"卡片（同上）
```

## D104 ★★ 不复制两份代码，用 `body[data-role]` 分角色

**看着最省事的做法**是把 index.html 拷一份改改。**但那是错的**：
```
复制两份 → 以后改一处要改两个地方 → 必然改漏一处
★ 这个项目里已经因为"改了一处忘了另一处"栽过好几次（D63 的产品名复发）
```

**实际做法**：一个文件 + 角色标记
```js
const ROLE = document.body.dataset.role || 'agent';
const ALL_TABS = [
  ['live','实时','agent'], ['chat','试一句','agent'], ['ho','人工','agent'],
  ['mytodo','我的问题','agent'],
  ['issue','问题处理台','dev'], ['kb','知识库','dev'], ['ch','渠道','dev'],
  ['model','模型','dev'], ['learn','学习','dev'], ['gov','治理','dev'],
];
const TABS = ALL_TABS.filter(x => x[2] === ROLE);
```
`dev.html` 就是同一份文件、`data-role="dev"`、换个标题。

**代价**：两个页面下载的是同一份（有点大的）JS。
**收益**：**只有一份逻辑**，永远不会出现"改了客服台忘了技术台"。

★ 对这个场景，这个取舍是对的 ——
  这份 JS 是本地部署的内网应用，不是公网首屏，多几十 KB 无所谓；
  而"两边行为不一致"是真正会出事的。
