# 人工回复时不要刷新页面

> 用户的反馈：
> 「客服或者销售发消息，也就是人工的时候，不要刷新页面，现在发现会刷新页面。」

---

## D101 ★★★ 「刷新」有三个来源，全都要治

**用户说的是"刷新页面"，但我查下来其实是三件事叠在一起：**

```
① 按「发送」之后  hoReply() 里写了  hoCur = null; loadHandover();
   → 详情整块重建
   → 滚动位置回到顶部、正在写的草稿被清空

② 每 20 秒的自动刷新  setInterval(loadHandover, 20000)
   → 同样重建详情
   → 客服正在看上面的对话，突然跳一下

③ 详情每次都是**全量重建**（innerHTML = 一坨新 HTML）
   → 没有做任何差异，所以即使内容没变也会"闪一下"
```

### 修法

**① 把「刷列表」和「刷详情」拆开**
```js
loadHandover()                    // 只刷列表（很轻，必须实时）
loadHandover({ detail: true })    // 才重建详情
```

**② 发送成功后只追加一条，不重建**
```js
// 旧：hoCur = null; loadHandover();     ← 整块重来
// 新：把刚发的话 append 到会话记录末尾，然后滚到底
const d = document.createElement('div');
d.innerHTML = '<div class="tl-who">客服…</div><div class="tl-bub human">' + esc(t) + '</div>';
wrap.appendChild(d);
wrap.scrollTop = wrap.scrollHeight;    // 滚到底，看得到自己刚发的
```

**③ 只有"真的有新的"时才重建详情**
```js
// 待处理条数变了 = 来新活了 → 才重建
await loadHandover({ detail: n !== _hoLastOpen });
```
★ 为什么用"条数"当信号：客户再来消息会生成新的待处理项，
  条数一变就说明有新的了。条数没变就什么都不动。

**④ 重建时保存并还原"现场"**
```js
const keep = {
  scroll: wrap.scrollTop,      // 滚动位置
  draft:  textarea.value,      // 正在写的草稿
  focus:  document.activeElement.id === 'hoText',
  caret:  textarea.selectionStart,   // 光标位置
};
// ...重绘...
wrap.scrollTop = keep.scroll;
textarea.value = keep.draft;
textarea.focus(); textarea.setSelectionRange(keep.caret, keep.caret);
```

**★ 第 ④ 条是"不刷新"的兜底**：即使因为别的原因重建了，
  客服也不会丢掉他正在写的东西。

## D102 ★★ 我用一个有 bug 的测试脚本，白查了一轮 `hoReply`

**现象**：测试报"发送后草稿还在、会话行数没变"，看起来像 `hoReply` 坏了。

**我做了**：
```
· 查了服务端接口 —— 好的（直接 curl 能发出去）
· 查了 JS 报错 —— 没有
· 查了函数定义 —— 只有一个，签名也对
· 又写了个独立诊断脚本 —— **能通**
```

**真正的原因**：测试脚本里写的是
```js
document.querySelector('.btns button').click()   // ← 点错了按钮
```
**页面上有多个 `.btns`，第一个不是「发送」。**

★ 而我之前用脚本改这一行时，**替换没匹配上**（缩进不同），
  脚本也没报错，于是"以为改了"其实没改。

**★ 教训（和 D99 是同一类）**：
> **改测试脚本本身也要验证"改成功了没有"。**
> 我在这上面已经栽过两次了（D59 的前缀替换、D99 的 `\n`、这次）。
> 所以：**脚本报"成功"只说明字符串写进去了，不说明有作用。**

**一个可用的做法**：改完之后 **grep 一下改后的内容**，
看到新代码真的在文件里，再跑。
