# 改：作品集不用序号标注项目

> 用户的反馈：「不要这种列项目，就是一 二 三 这种」

---

## D111 ★★ 序号不是信息，角色定位才是

**现象**：三个项目的 badge 是
```
销售报表 Agent  →  主力
AI供应链        →  在研
AI客服          →  第三个     ← 只是个序号
```

**★ 两个问题**：
```
① 「第三个」没有任何信息量 —— 它只说"它是第三个"，不说明它是什么
② 42×42 的方块装不下三个字 —— 截图里"第三/个"换行了，看着像坏了
```

**修法**：换成描述**它在整体里的角色**的词。
```
主力  →  最成熟、最该先看的
在研  →  还在做
最新  →  刚做完的这个
```

★ 中间试过「上线」，但查了一下发现**三个项目都有 publicUrl、都真挂在公网上** ——
  那个词不构成区别，而且卡片状态行本来就会写"已上线"。换掉。

---

## D112 ★★ 顺手发现卡片状态把"真上线"这件事藏起来了

**原来的逻辑**（线上模式）：
```js
var live = (window.SITE_MODE === "public")
  ? '可现场演示'          // ← 所有项目一视同仁
  : ...本机探测...;
```

**★ 问题**：
```
· 三个项目其实都挂在公网上，卡片上却只写"可现场演示"
  —— 访客不会点进去，因为他以为只有面试现场才能看
· 而卡片上那个「打开演示 ↗」链接只在**本地模式**才渲染
  （因为本地的 url 是 127.0.0.1，公网上渲染成死链是对的）
→ 于是公网访客：既看不到"已上线"，也没有可点的入口
```

**修法**：区分"有公网地址"和"没有"
```js
var online = (p.demo && p.demo.publicUrl) ? p.demo.publicUrl : "";
var live = (window.SITE_MODE === "public")
  ? (online ? '已上线 · 点右边直接打开' : '可现场演示')
  : ...;
// 底部：线上有 publicUrl 就给真链接；没有的不渲染（避免 127.0.0.1 死链）
```

**★ 这条的普遍意义**：
> **"不能渲染死链"和"该给真链接"是两件事，别用同一条规则处理。**
> 原来的写法是"线上不给链接"（防死链），
> 但它把"有公网地址的那些"也一起禁了 ——
> 防死链的目的达到了，可访客也失去了唯一能点的入口。
