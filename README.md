## 这三个项目共同的核心判断

> **业务数字不许大模型算，全部由程序算出来；AI 只负责听懂人话和组织语言。**

这不是一句口号，是落到代码结构里的：

| 做法 | 具体是什么 |
|---|---|
| **数字有出处** | AI供应链里所有业务数字走统一契约（值 / 状态 / 来源 / 证据锚点），前端不算任何业务数字 |
| **空数据不补 0** | 没有真实数据时返回 `NO_DATA` 并给出原因，界面显示「—」；`0` 和「没数据」是两件事 |
| **该拦的代码层拦** | 报价 / 折扣 / 合同 / 收款账户命中即转人工，**根本不调用模型**（不是写提示词求它别乱说） |
| **AI 不生成证据** | 线索研究的「公开资料原文」刻意**不给 AI 生成按钮** —— 它是逐字回验的依据，AI 写了验证就失效 |
| **生成物必须人工确认** | AI 生成的内容只填进表单、打上「未复核」标记，人确认后才入库 |
| **出处不给客户看** | AI客服 的回答里不出现任何资料名 —— 那些是内部文档（《报价底线》《客户分级标准》），给外部客户看等于泄露内部结构。溯源仍然留着，只是给自己人看 |
| **降级链不含免费模型** | 很多免费模型的条款允许用输入训练，而输入是公司内部资料和客户对话。省下的 API 费用不值这条 |

## 各自看什么

### AI供应链 · 业务助理

给一家卖 AI 算力方案的公司用的业务工作台：客户、商机、项目、营销内容、
获客研究、风险、报告、方案集中在一处。老板可以直接问数据，业务员在里面干活。

- 规模：97 条接口 · 19 张表 · 23 个前端页面 · 60 条决策记录
- 入口文档：[`ai-supply-chain/docs/TODO_HANDOFF.md`](ai-supply-chain/docs/TODO_HANDOFF.md)
- 取舍与被放弃的方案：[`ai-supply-chain/docs/DECISIONS.md`](ai-supply-chain/docs/DECISIONS.md)

### 销售报表 Agent

用大白话问销售数据，也能把手头导入的资料当知识用。回答里每个数字都能在
确定性计算结果里找到出处，口径（区间 / 排除规则 / 变化率分母）必须写进回答。

- 规模：1388 项自动化测试全通过 · 86 条真实问法评测集
- 入口文档：[`sales-agent/README.md`](sales-agent/README.md)

### AI客服（中小企业版）

接企业**已有的**异构知识源（共享盘 / Word·Excel·PDF / 网页 / 内部 API）
与渠道（网页挂件 / 飞书 / 企微），用口语回答内部员工和外部客户。
企业不需要为它整理任何东西 —— 这是这个项目的立足点。

「转人工」不是一个动作，是三档不同策略：

| 档 | 触发 | 处理 |
|---|---|---|
| 简单 | 寒暄、"你是做什么的" | 不查资料，直接答 |
| 中级 | 检索命中但不够确定 | **先答一次并请用户确认**；重复提及才转人工 |
| 高级 | 议价 / 退款 / 投诉 / 合同 | 直接转，一个字都不答 |

「问流程」（怎么报价）和「要数字」（便宜点）分开处理：前者由 AI 答流程
并把该问的信息问全，人工接手时拿到的是一条**完整需求**。
上线前转人工率接近 100%，调完 15%（16 句真实场景实测，剩下 3 条全是真该转的）。

- 规模：349 个断言 / 9 个测试文件 · 113 条决策记录 / 21 份文档
- 入口文档：[`ai-customer-service/docs/决策记录-边界.md`](ai-customer-service/docs/决策记录-边界.md)（转人工率那次修复的完整推演）
- 全部决策：[`ai-customer-service/docs/`](ai-customer-service/docs/)

## 关于密钥

本仓库**不含任何 API Key、数据库口令或服务器凭据**。

- `.env` 由 `.gitignore` 排除，且从未进入过提交历史
- 演示环境的账号是专门为公开演示创建的，与开发环境不同
- 部署脚本里的服务器信息已替换为占位符
- AI客服 里**连"禁止出现的口令清单"都不进仓库**：护栏测试
  `scripts/smoke9.py` 要检查代码里有没有真实口令，就得知道它们是什么 ——
  但那会让护栏本身变成密钥的藏身处。所以真实值放在被 gitignore 的
  `.forbidden` 里，读不到就跳过那两条检查并打印警告

## 每个项目：优缺点 / 学到什么 / 技术 / 后续

面试官最想知道的其实是**缺点**和**踩过什么坑**，所以我把它们写在最前面。

| 项目 | 复盘文档 |
|---|---|
| AI客服（中小企业版） | [`ai-customer-service/项目复盘.md`](ai-customer-service/项目复盘.md) |

### AI客服 · 摘要

**一句话**：把"AI 可能编事实"的每个位置都堵死，再让 AI 只做它擅长的 ——
听懂人话、组织语言。剩下的（什么该自动答、什么该转人工、什么该说不知道）
是产品决策，不是模型能力。

**强在哪**

- 事实由程序算，模型只组织语言；四档降级链任何一档都不许编
- 「转人工」是三档策略不是动作：上线前转人工率接近 100%，现在 **15%**
- 溯源留着（`qa_log`），但**出处不给客户看** —— 资料名是内部信息，三层堵
- 人工接管后**会话真的在人工手上**，只有人工点「结束接管」才交还 AI
- 学习闭环带关卡：先进 `pending`，跑一遍评测确认没变差才生效
- **401 条断言 + 真浏览器复验 + 122 条决策记录**

**弱在哪**（真的缺点）

- **检索是字面匹配不是向量** —— 问「物流时效」而资料写「时效承诺」就命中不到。
  不用向量是因为目标客户机器常只有 2G 内存。★ 我选择"宁可说没找到，也不编"，
  但这个取舍确实让召回率不如向量方案
- **飞书/企微没用真实企业账号验证过** —— 协议按公开文档实现，
  离线测了签名和 AES 往返，但没有真实租户跑过收发。这一条我不敢说"能用"
- 钉钉只有配置界面，适配器没实现
- SQLite 单进程（`workers=1`），并发上去会排队
- 前端原生 JS 无框架 —— 状态管理靠手工，已经踩过白屏和轮询竞态
- 2.5 秒防抖是全局的，对打字快的人有延迟（理想是按人自适应）
- 降级链刻意不用免费模型（合规），所以每条回答都真花钱 ——
  这是我**主动选择让客户多花钱**的地方
- 微调没做，而且我认为事实类问题不该靠微调解决
- 评测集只有几十条，样本量小

**踩过的坑（学到什么）**

1. **把「一句话处理完了」和「会话归人工负责」混成一件事** ——
   数据模型的粒度错了，行为就会错；客服接管的是人，不是那一句话
2. **护栏本身成了密钥的藏身处** ——
   写"不许出现密钥"的检查表时，我把真实口令写进了代码。
   这比忘记 gitignore `.env` 更隐蔽：它看起来在**防**密钥
3. **我报过假的"全部通过"** ——
   "跑过测试"和"跑过全部测试"是两件事。报数字之前必须真跑一遍
4. **nginx 给 .js 设了 7 天缓存** ——
   部署完用户最长 7 天看到旧版；它不是服务端问题也不是代码问题，
   排查时极容易走错方向
5. **反复踩同一个坑（中文引号写进 Python）→ 把它变成自动检查**，
   而不是每次靠"下次注意"
6. **补丁"报成功"不等于改上了** → 改完先 grep 确认，再跑测试
7. **先抓证据再改代码** —— 排查"发消息就刷新"时先证明页面根本没重载，
   否则会去修一个不存在的问题

**技术栈**

```
Python 3.11 · FastAPI · SQLite · httpx
检索：中文 2-gram + BM25 + 分块（刻意不引向量库/torch —— 2G 内存约束）
解析：python-docx / pypdf / openpyxl（共享盘里的 Word/Excel/PDF 直接读）
抓取：标准库 HTMLParser（少一个依赖）
渠道：网页（outbox + 轮询）/ 飞书 / 企微（AES）/ 模拟
前端：原生 JS 单页无框架，双角色靠 body[data-role] 过滤
模型：DeepSeek，四档降级
部署：systemd + nginx 子路径反代（多个项目共用一个端口）
测试：自写断言 + CDP 真浏览器复验
```

**后续**

```
近期：钉钉适配 · 真实飞书/企微验证 · 转人工主动推送通知 · 评测集扩充接 CI
中期：检索加一路向量做补充（不是替代）· 防抖窗口按人自适应 · 知识源增量同步
不做：微调（改不了"资料里没有"）· 多实例集群（过度设计）
      · 帮客户"整理知识库"（那是另一个产品）
```

## 我是怎么工作的


需求与验收标准先写清楚 → 方案先送评审 → 实现交给 AI 工具 →
**在真实页面和隔离环境里逐条复验** → 发现的问题走「定位 → 修复 →
针对性测试 → 回归」并留决策记录。

判断和验收由我负责，重复实现交给工具；错了算我的。

具体到这四个项目，开发过程中 AI 造成的真实缺陷（界面出现 markdown 记号、
断言没跟着行为改、检查脚本空跑、子路径拼错一层 `/api`、标签页的 `let`
写在调用之后导致页面空白、nginx 缓存设 7 天导致部署后用户看到的还是旧版）
都是由复验抓出来的，每一条都记在决策记录里 —— **包括我自己的测试写错的那几次**。
