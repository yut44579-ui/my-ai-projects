How I work

我的工作流程（可复制成标准动作）

这套流程解决的是"AI 说完成了，但东西其实不对"。每一步都有它的产出物，不是口号。

01

需求变验收

先把目标翻译成"什么算通过"，写下来再动手。

02

先摸清现状

读真实代码与运行状态，不靠猜；口径冲突先列事实。

03

方案先评审

动代码之前先送双审；两家都过才放行，单审不算。

04

真实页面核对

打开页面亲手点，核对数据与文案；不看产物不算验证。

05

独立复验

用自己的素材去问，不用它自测的样本——自测全过不等于能用。

06

归因与留痕

失败样本逐条归因；结论写进提交与验收记录，可复核。

停止条件只有四类：跨模块方案分叉 · 业务规则冲突 · 超出授权 · 实际阻断。普通编码/测试/提交/汇报都不构成停下来等指令的理由。

▷
销售分析助手真实调用 trace点下面的问题，重放当时的执行链路

这些记录从哪来

  • 问答链路：本机 POST /api/chat 的真实调用（含判路档位、取数工具与确定性计算耗时）
  • 评测集：86 条真实问法的跑分记录（含 11 条没通过的，一条没删）
  • 资料问答：外部文件导入后的检索与出处记录（含"没找到"的那次）
  • 独立复验：我自己造素材抓出的缺陷前后对照（修前 0 字回答 → 修后带出处）

为什么不做成"实时试用"？

  • 实时服务需要 24 小时在线的机器，而且每个访客的每次提问都会真实消耗 API 额度
  • 放出去还要防陌生人刷 —— 这是我要先做限流和鉴权隔离的原因，不是偷懒
  • 所以线上先给真实回放；面试现场可以直接开本机真实系统当场操作

作品集导览（离线）预置答案 · 点击问题即回答

为什么用"离线问答"而不是直接上模型？

  • 可信：给出的每条答案都写死在数据文件里，能被逐条核对，不会现场编。
  • 可解释：它同时演示了"Agent 控制页面"的思路——回答里带跳转，把人带到证据所在页面。
  • 不越界：不接入个人记忆、技能库与执行工具，避免把私有工作流和公司数据混进来。

它可以带你去哪

  • 项目详情页：背景 / 我的职责 / AI 协作部分 / 结果 / 局限
  • 每个指标的来源文件与样本口径
  • 项目的本地演示入口（真实服务，不是截图）
Limits

这个项目现在还不是什么

写清楚边界，比写亮点更能说明我知道自己在做什么。

如实说明

  • 是本地可运行的演示原型，不是生产系统；数据是公开的电商交易数据集（UCI Online Retail，2010-12 ~ 2011-12）。
  • 指标来自评测集，样本量有限（86 条真实问法），不等于线上表现；剩下 11 条没通过的样本一条没删。
  • 数据只有收入侧：没有成本字段，所以 ROI / 毛利一律明说"给不了"，不拿行业平均凑。
  • 检索是字面匹配（中文 2-gram + 轻量 BM25）：换个说法可能漏，但它选择说"没找到"，不会编。
  • 代码由 AI 协作实现：我负责需求拆解、方案取舍、验收判据与复验；这一点我从不含糊。
  • 做不动的问题我会写"未解决"，而不是用"基本可用"糊过去。
