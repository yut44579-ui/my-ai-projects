# 需求文档 · sales-report-agent

> 一句话：**用户说人话 → AI 自己搞明白 → 自己取数算数 → 出成品报表文档（可定时自动重复）**

## 1. 业务痛点

| 现状 | 问题 |
|---|---|
| 每周手动做销售报表 | 从数据库/Excel 里导数据、拉透视表、算指标、贴进固定格式——**每次 1-2 小时** |
| 员工表达需求很随意 | 说的是"做个上周销售汇总""**像这个表这样**"，不是精确的字段口径清单 |
| 人工算容易错 | 公式拉错、漏行、口径不一致；**错了还很难发现**（数字看着都像对的） |
| 沿用工具门槛高 | BI 工具（Metabase 等）要手工配图表；写 SQL 要懂库结构 |

## 2. 目标用户

**单用户（本人）**：需要每周出固定格式销售报表的人，不会/不想写 SQL。

## 3. 自动化目标

```
输入：大白话需求（可附参考物：已有 Excel 报表 / 截图）
  ↓ AI 理解 → 出方案 → 用户确认（必须）
  ↓ 固化成任务
输出：定时的成品报表（Excel，保留参考物样式）+ 文字解读与建议
```

**核心机制**：**首次理解 → 确认 → 固化 → 之后自动重复**（不是每次重新理解——保证同一任务产出稳定）。

## 4. 成功指标（评估驱动 · 这是分水岭）

| 指标 | 定义 | 目标 | 测量方式 |
|---|---|---|---|
| **数字准确率** ⭐ | 生成报表的数字 vs 人工核算一致率 | ≥ 98% | 人工核算 50 个数据点 |
| **需求理解准确率** | AI 出方案 vs 人工期望（指标/数据源/口径）一致率 | ≥ 85% | 测试集人工标注对比 |
| **格式还原度** | 输出文档 vs 参考物的结构/样式一致 | ≥ 90% | 逐项检查（列/表头/样式） |
| **端到端成功率** | 从需求到成品一次通过率 | ≥ 80% | 全流程跑测试集 |
| **失败归因分布** | 错在哪一步（理解/映射/取数/计算/渲染） | 有分布即可 | 失败案例逐条归因 |
| **人工确认必要性** | AI 主动提问（不瞎猜）的比例 | 边界场景 100% | 边界测试集验证 |

**留出集**：测试集 8:2 切分（固定随机种子），20% 只在最终验收跑。

## 5. 范围（MVP · 现在必须做）

| # | 功能 | 说明 |
|---|---|---|
| 1 | 数据接入 | Excel/CSV 上传 + MySQL 连接 |
| 2 | 数据字典 | 扫描字段生成"可用数据清单"（给 AI 映射用） |
| 3 | 建任务 | 大白话 + 参考物（Excel 样本优先）→ AI 出方案 → **用户确认** |
| 4 | 数据映射 | AI 列候选 → 用户选（找不到就提问） |
| 5 | 执行引擎 | **定时 + 手动**触发 → 取数 → **代码计算** → 渲染 Excel（保样式） |
| 6 | 产出 | Excel 文件 + AI 解读建议 → 页面查看/下载 |
| 7 | 执行记录 | 时间/状态/文件/错误原因（可追溯 + 审计） |
| 8 | 失败处理 | 数据源断/字段缺失 → 明确报错，**不产出错误文档** |

## 7. 数据说明

| 项 | 内容 |
|---|---|
| 主数据集 | **UCI Online Retail**（`data/Online Retail.xlsx`，541,909 行真实交易） |
| 字段 | InvoiceNo / StockCode / Description / Quantity / InvoiceDate / UnitPrice / CustomerID / Country |
| 时间范围 | 2010-12-01 ~ 2011-12-09（**适合做周报**：54 周） |
| 规模 | 38 国 / 4372 客户 / 合计 £9,747,747.93 |
| 用途 | 真实数据演示 + 派生 mock 数据（测试集场景） |
| 已知脏数据 | 客户 ID 有空值、有退货（Quantity<0）、有取消单（InvoiceNo 以 C 开头） → **正好用作边界测试** |

## 8. 测试集规划（≥50 条）

| 类型 | 条数 | 内容 |
|---|---|---|
| 正常需求 | 16 | 给样本型 / 大白话型 / 混合型（"像这个，但加环比"） |
| 边界情况 | 16 | 空数据 / 字段改名 / 时间范围特殊 / 多指标 / 退货与取消单 / 空客户 |
| 需人工确认 | 18 | 找不到表 / 口径歧义（"销售"含不含退货？）/ 需求含糊 → **AI 必须提问** |

**对齐要求**（工作流）：mock 数据的时间戳与字段必须围绕测试用例设计，不能随机分布。

## 9. 主要风险

| 风险 | 影响 | 对策 |
|---|---|---|
| AI 理解错需求 | 报表全错 | **强制人工确认**（生成前给方案） |
| LLM 算错数 | 数字不可信 | **数字全由代码算**（LLM 只写文字） |
| 参考物样式丢失 | "不像这个" | openpyxl 原地改，不用 pandas 重建 |
| 数据源变更 | 任务失败 | 明确报错 + 候选字段让用户重选 |
| 同任务产出不稳定 | 无法信任 | 首次理解后**固化规则**，不每次重新理解 |
| 评估自己骗自己 | 面试被问倒 | 留出集 8:2 + 口径透明 + 失败样本不删 |
