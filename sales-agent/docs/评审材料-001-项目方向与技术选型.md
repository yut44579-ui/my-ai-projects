## 一、项目摘要

**一句话**：把"每周手动做销售报表"变成"说一次，之后自动出"。

- **目标用户**：单用户（本人）——需定期出固定格式销售报表、不会/不想写 SQL
- **痛点**：导数据→拉透视→算指标→套格式，每周 1-2 小时，易算错且难发现
- **核心机制**：
  1. 用户说人话（"做个上周销售汇总"／"照这个表做"／"我要这个"，可附参考物：Excel 样本或截图）
  2. AI 理解 → **出方案给用户确认**（必须确认，防错）
  3. 找不到数据 → **列候选让用户选**（不瞎猜）
  4. 固化成任务 → 定时自动：取数 → **代码计算** → 渲染 Excel（保留参考物样式）→ AI 写解读
- **MVP 范围**：数据接入（Excel/CSV+MySQL）、数据字典、建任务、数据映射、执行引擎（定时+手动）、产出、执行记录、失败处理
- **非目标**：BI 仪表盘、多用户/权限、向量数据库、LangChain、在线编辑 Excel、实时流处理、多数据源
- **数据**：UCI Online Retail（541,909 行真实交易，2010-12~2011-12，54 周）
- **成功指标**：数字准确率≥98%、需求理解准确率≥85%、格式还原度≥90%、端到端成功率≥80%
- **项目性质**：求职作品集 + 自己真用（两者都要，先按作品集标准做）

## 三、技术决策清单（请逐条评审）

| # | 决策 | 否掉了谁 | 理由 |
|---|---|---|---|
| D1 | 后端 FastAPI | Django / Flask | 轻量、本人熟悉、与 pandas/openpyxl 生态好 |
| D2 | **不用 Agent 框架** | LangChain / LlamaIndex / LangGraph | 流程固定（解析→确认→固化→执行），非自主循环；减少黑盒与依赖 |
| D3 | **不用向量数据库** | Chroma / FAISS / Milvus | 需求是结构化字段映射，不是语义检索 |
| D4 | **数字一律代码算**（LLM 只写文字） | 让 LLM 算数 / 让 LLM 生成 SQL | LLM 算数不可靠；Spider 2.0 数据支撑；报表价值就是数字准 |
| D5 | Excel 用 openpyxl 原地改 | pandas.to_excel 重建 | 重建会丢合并单元格/字体/列宽/条件格式；用户要求"像这个" |
| D6 | 调度用 APScheduler | Celery+Redis / 系统计划任务 | 单用户单机，进程内定时够用 |
| D7 | 前端原生 HTML/JS | Vue / React | 只有 4 个页面 |
| D8 | 存储 MySQL + 本地文件 | 对象存储 / 纯文件 | 单机自用；产出文件用户要能直接打开 |
| D9 | **首次理解→固化**（不每次重新理解） | 每次自然语言重新解析 | LLM 有随机性，同样输入可能产出不同报表；报表必须可重复 |
| D10 | 失败不产出错误文档 | 降级输出（部分数据） | "看起来正常但数字错"的报表比没有更危险 |
