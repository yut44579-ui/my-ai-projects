# 前端展示规范（用户明确要求 · 违反即返工）

> 用户原话：「要记住你图片这些有些在代码里面有出现就行了 不要出现在前端影响观看感 比如 实现的过程这些 代码块」

## 铁律：前端只展示业务内容，技术实现留在代码里

### ❌ 绝不允许出现在前端界面
| 类别 | 具体例子 |
|---|---|
| **代码块** | JSON 片段、请求体、参数对象 |
| **接口信息** | `/api/chat`、`POST`、`GET`、`openapi` |
| **开发阶段标注** | `TASK-004`、`STEP A`、`P2` |
| **内部代号** | `D16`、`D4`、R005 这类评审/口径编号 |
| **实现过程说明** | 「走哪条链路」「闸门怎么校验」「工具白名单几个」 |
| **技术性提示** | 「与 loading 三态联动」「同一套确定性计算」「来自任务绑定」 |
| **数据结构术语** | 哈希、schema、repository、端点、payload |
| **构建/版本信息** | `v0.3`、`2eac420+dirty`、构建号 |
| **文件元数据** | `file_id`、数据 SHA256、upload 目录路径 |
| **权限实现细节** | 「角色：owner（尚未做鉴权）」「权限与安全：未启用（TASK-011）」 |

### ✅ 前端只应该展示
| 类别 | 正确例子 |
|---|---|
| 业务数据 | 表格、数字、图表、排行 |
| 业务语言的状态 | 「正在分析…」而不是「loading state」 |
| **对业务有意义的**边界提示 | 「数据集中没有区域字段，无法按区域分析」（业务语言，不是代码语言） |
| 人话错误提示 | 「没有配置可用的模型服务」而不是 `DEEPSEEK_API_KEY missing` |
| 用户身份 | 登录时填的名字（或「游客XXXXX」） |

## 已发现的违规位置（要在 STEP A 一并清理）

| 位置 | 现状 | 处理 |
|---|---|---|
| 客户分析页 | 「客户分析走自然语言问答…本页不单独铺一张客户明细表」 | → 换成正常表格 |
| 数据管理页 | 「当前可用的数据文件 · 来自任务绑定」+ `file_id` / 哈希列 | → 改成「数据源」+ 业务字段 |
| 左侧栏底部 | 「版本：0.2.0」「角色：owner（尚未做鉴权）」「权限与安全：未启用（TASK-011）」 | → 撤掉或改业务语言 |
| 补充说明行 | 「数字闸门：已核对（合法数字 19 个）」 | → 已撤，勿再加回 |
| 页面正文 | 任何 `TASK-` / `/api/` / `POST` / `openapi` / `白名单` | → 一律不出现在前端 |

## 原型说明 ≠ 最终前端（重要区分）

`docs/原型-*.html` 里的「参考了 Dribbble…」「属 TASK-011」「与 loading 三态联动」这类**是写给你看的说明**，
不属于最终前端界面。**最终前端不含这些**。
