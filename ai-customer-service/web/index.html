我报的问题

看看处理到哪一步了
看到哪里不对，点右下角红色按钮报上去。你不用懂技术 —— 只要说哪儿不对，剩下的（哪句问答、AI 当时怎么判的）系统会自己附上。

怎么用

三步，不用记任何东西。
① 在哪儿看到不对就在哪儿点
「实时」页每条问答旁边有「⚠ 这条不对」； 「人工」页有「⚠ 报个问题」；右下角还有个常驻的红按钮。
② 选个"哪儿不对" + 写一句话
就这两样。别的都不用填 —— 系统自动附上那条问答的完整记录、前后对话、命中的资料。
③ 等结果
技术处理完之后，这里会显示「技术说已经处理好了，你去试试」。 你去试，好了就点确认；没好就点"还没好"，会打回给技术。
★ 为什么要你确认：技术说修好了、 但改的地方和你遇到的不是一回事 —— 这种事很常见。 你不点头，这个问题就不算完。

问题处理台

按 状态 → 严重程度 排。 自己说修好了不算数 —— 要报问题的人点「好了」才算关闭。

这边怎么用

客服和销售在系统里看到不对的地方，点右下角红按钮报上来。
① 看问题
左边一条条点开，能看到系统自动附的现场 —— 哪句问答、AI 判成了哪一档、检索质量、命中了什么资料、最近的报错。
② 接手并修
点「我来处理」，状态变处理中，别人就知道有人在看了。
③ 填解决方案并提交
写清楚改了什么，选个类型（知识库缺资料 / 代码 bug / 配置问题…）。 提交后状态是「已解决（等确认）」，不是关闭。
④ 等报的人确认
他说「好了」→ 关闭。他说「还没好」→ 打回处理中， 并带上他的补充说明。
★ 为什么非要报的人确认：技术说修好了、 但改的地方和用户遇到的问题不是一回事 —— 这种事极其常见。 报的人不点头，这个问题就不算完。

怎么选

四个渠道的能力和门槛差别很大，选错了会卡在部署上。
飞书 · 最省事
支持长连接，不需要公网地址、不需要证书。私有化部署的首选。
企业微信 · 必须公网
回调强制要求公网 HTTPS，不能用 IP:端口、不能自签证书。 服务器在内网就接不了。
网页挂件 · 零门槛
不需要任何平台账号。一行 script 贴上去就行。
★ 如果客户服务器在内网：先推飞书。企微要么配公网入口， 要么用内网穿透 —— 后者要跟客户说清风险（穿透服务的稳定性不归我们管）。

模型配置

改完立即生效，不用重启。不填 Key 也能用 —— 只是 AI 相关功能会降级成"直接把查到的原文给你"，不会假装答了。

降级顺序

AI 用不了的时候不是直接崩，而是一档一档往下退。
第 1 档 · 主模型
就是左边配的那个
第 2 档 · 便宜档模型
同厂商的便宜模型，数据条款一致
第 3 档 · 不调模型，原文直出
零成本、零编造风险，用户至少拿到信息
第 4 档 · 只转人工
并告诉用户"已转人工"，不让他干等
★ 刻意不把「免费模型」放进来：很多免费模型的条款允许用输入训练，而这里的输入是公司内部资料和客户对话 —— 那是合规红线，比省下的那点 API 费用严重得多。
