# 人工接管后 AI 闭嘴 + 消灭"刷新感"

> 用户的反馈：
> ① 「你客服接入了之后，就一直是客服谈话了，不要又弹出其他的」
> ② 「不要客服一发消息就刷新页面啊，不要刷新，发一个刷新一下，什么鬼啊」

---

## D105 ★★★ 人工接管后，AI 必须**完全沉默**

**现象**：人工已经接管了，用户又发一句「666」，AI 还回一句
"没太确定你想问什么"。

**★ 两个后果，第二个更严重**：
```
① 用户懵了：不是有人接管了吗？怎么又来个机器人？
② ★ 状态自相矛盾 —— 界面上那个转圈写着
   「正在为你转接人工客服…」，然后 AI 自己又答了一句。
   **系统在打自己的脸。**
```

### 修法：在**任何处理之前**拦下来

放在很靠前的位置（急停之后、意图判定之前）：
```python
ho = _handover_active(tenant_id, channel, user_ref, conversation_id)
if ho and not shadow:
    return finish(Answer(
        text="",                    # ★ 空字符串 = 什么都不发
        decision="silent",
        reason=f"这个会话已经有人工在管（#{ho['id']} · {ho['status']}）—— "
               f"AI 不再插话，避免和客服说的话打架",
    ))
```

**★ 连 `open`（还没人接）也要沉默**：
```
我们已经跟用户承诺"正在转接人工"了 ——
这时候 AI 再开口就是自相矛盾。
```
**★ 但消息照样记进 qa_log** ——
人工在工作台能看到客户又说了什么（他正在处理，需要知道）。

**★ dispatch 层要专门处理 `silent`**：什么都不发，但要计数（能看见拦了多少）。

**实测**：
```
转人工后收到    waiting:正在为你转接人工客服…
人工接管        {"ok": "张工 已接管"}
接管后发「666」  新增只有 taken:客服已接入
★ AI 有没有插话  ✅ 完全沉默
客服回复后       human:报价要工程师看过图纸才能定…
```

## D106 ★★ 「刷新」不是真的重载，是**列表在无脑重建**

**先做的事：抓证据，而不是猜。**
```js
m.dataset.probe = 'PROBE-A'     // 在被观察的 DOM 上打个标记
// 如果它被重建，标记就没了
cheng
cdp.on('Page.frameNavigated', ...)   // 监听真的导航事件
```
**结果**：
```
客户挂件  标记还在 ✅ 节点 3→4（追加）✅ 导航事件：无
客服台    标记还在 ✅ 行数 21→22（追加）✅ 导航事件：无
```

**★ 所以页面根本没重载。那用户看到的"刷新"是什么？**

找到两处：
```
① 客服台发完消息 → loadHandover() 无条件  $('#holist').innerHTML = ...
   即使列表一条没变，浏览器也要重新解析、重新排版一整块 DOM
   → 左边那个列表**闪一下** = 用户说的"刷新"

② 客户挂件每条消息都 scrollTop = scrollHeight
   → 用户正往上翻看历史，来一条就被弹回底部
   → 那个感觉也非常像"被刷新了"
```

### 修法

**① 列表内容没变就不重建**（指纹比较）
```js
const sig = d.items.map(x => x.id + ':' + x.status).join('|');
if (sig !== _hoListSig) { _hoListSig = sig; $('#holist').innerHTML = ...; }
```
★ 而且**不强制重绘** —— 发完消息列表可能真的变了（那条从待处理里消失），
  但那是靠指纹比较发现的；强制重绘的话，即使没变也会闪一下。

**② 挂件只在"本来就在底部"时才自动滚**
```js
function smartScroll() {
  const m = $('#msgs2');
  if (m.dataset.stick !== '0') m.scrollTop = m.scrollHeight;
}
// 用户手动往上翻 → dataset.stick = '0'，就不跟了
```

**③ 顺手把客服说的话改成绿色气泡 + "客服"标签**
```
原来是 add('a', ...) —— 用的还是 AI 那种白气泡
★ 用户得能一眼看出"这句是人说的"，否则他会以为还是机器人在答
```

**实测**：
```
发送前  items 15, rows 22
发送后  listProbe=LIST ✅  itemProbe=(没了)  wrapProbe=WRAP ✅
导航事件 （无）
```

## D107 ★ 先抓证据再改代码

这一轮我做对的一件事：**没有直接去"修刷新"**，
而是先打标记、监听导航事件，**证明"到底有没有重载"**。

```
如果我不查就改，很可能会去优化"页面重载"（那根本不存在），
而真正的问题（innerHTML 无脑重建 + 滚动跳底）反而没动。
```

**★ 一个可复用的做法**：
```
要判断"某块 DOM 有没有被重建"，就在它上面打一个 data 标记。
重建了标记就没了 —— 比看代码猜可靠得多。
```
