# 边界：不该转人工的一律不转

> 用户的批评原话：
> 「你的回复不要随便就接入人工，AI 要判断啊，要有边界。
>   不是我随便发一句话就直接接入人工，这样不是会加重客服或者销售的压力？」

**他说得对，而且这个问题很严重。** 我看了下当时的人工队列：

```
"工作台"      → 转人工    ← 人工也不知道他要问什么
"你是干嘛的"   → 转人工    ← 这明明该 AI 自己答
"工作台呢"     → 转人工
"你们能便宜点吗" → 转人工    ← 但销售拿到这条也没用
```

**结果是客服的队列被无意义的消息淹掉**，真正紧急的那条反而没人看。

---

## D89 ★★★ 转人工的比例必须压下来，否则这个系统是负价值

**★ 这条要写清楚，因为它容易被忽略**：
```
转人工不是"安全"，是**把成本转嫁给客户的人**。
转得越多，客户越觉得"这个 AI 没用，还不如我直接找客服"。
而客服那边收到一堆没法回答的消息，也会觉得"这系统在给我添乱"。
```

**★ 判断标准**：一条消息转到人工之前，先问一句
> **"人工收到这条，能比 AI 多做点什么？"**
> 如果答案是"他也不知道要干什么" —— 那就**不该转**。

### 修之前的比例 vs 修之后

```
修之前：几乎全部转人工（"工作台""你是干嘛的"都转）
修之后：13 句里只有 2 句转（15%）
```

## D90 ★★★ 风险分两档：「要数字的」和「问流程的」

**这是这一轮最重要的结构改动。**

### 硬风险（HARD）→ 直接转，一个字都不答

```
议价让价    便宜点 / 打折 / 最低多少 / 能不能让
具体报价    报个价 / 多少钱 / 价格是多少
退款诉求    要退款 / 想退货 / 索赔
投诉纠纷    投诉 / 起诉 / 曝光 / 差评
法律合规    违法 / 侵权 / 专利 / 保密协议
个人信息    身份证 / 银行卡 / 验证码
合同承诺    签合同 / 保证金 / 账期 / 定金
```
**理由**：答错一次就是真金白银的损失或法律风险，"先答一下看看"这个念头本身就是错的。

### 软风险（SOFT）→ ★ AI 先答流程，**并且把该问的问全**，不转人工

```
报价流程    怎么报价 / 报价要多久 / 需要提供什么资料
合同流程    合同怎么签 / 签约流程
退换流程    怎么退货 / 退换政策
```

**★★ 为什么这一档是关键**：
```
一条"能报个价吗"直接甩给销售 → 销售拿到也没用，
                              他还是得回头问"什么零件、什么材料、多少件"
→ 让 AI 先答流程 + 把该问的问全
→ 人工接手时拿到的就是**一条完整的需求**，而不是一个待澄清的问题
```

**实测效果**：
```
问「怎么报价」
→ 报价这块得先走内部核价流程，您把需求给到我这边，我帮您转给对应的同事去核算。
  您这边具体是要报什么零件，用的什么材料，精度要求大概到什么程度？
                                    ↑ ★ 该问的全问了
```

**★ 但硬边界一点没松**：提示词里写死「**绝对不许**说出任何具体数字：
价格、折扣、比例、天数、金额、期限，一个都不能有」。

## D91 ★★ 看不懂在说什么 → AI 反问，不是转人工

```
"工作台" / "测试" / "???" / "嗯"
```

**★ 这类转人工是纯浪费** —— 人工也没法回答"工作台"这三个字。

**修法**：AI 反问澄清，最多 **2 次**，问不出来才转人工。

**澄清话术不能像在怼人**：
```
✗ "你什么意思？"
✓ "没太确定你想问什么。你可以直接说，比如：
    · 某个具体的产品或业务问题
    · 想查什么资料（制度、流程、政策）
    · 想找人联系你
   也可以直接留个电话，我让人打给你。"
```
★ 要**给出可能的方向**，让用户点一下就能继续，而不是让他自己想。

**★ 为什么是 2 次**：1 次太少（他可能只是没组织好语言），
3 次太多（会让人觉得在踢皮球）。

## D92 ★★★ `quality=None` 和 `quality=0` 是两件完全不同的事

**★ 这是修 D89 时引入的回退，很值得记。**

**现象**：边界改完之后，**所有需要查资料的问题都被反问了一遍**：
```
「打样要多久」    → "没太确定你想问什么"   ← 资料里明明有答案
「有哪些资质认证」 → "没太确定你想问什么"   ← 资料里明明有答案
```

**原因**：
```
分级函数被调用两次：
  第一次：检索**之前**，只能填 quality=0.0
  第二次：检索**之后**，填真实质量

而 0.0 会落进"检索没命中的分支" → 判成"先澄清"
→ 于是所有问题在检索之前就被拦下了，**检索根本没机会跑**
```

**★ 根因是语义混淆**：
```
quality = None  →  还没查过资料        ← 应该放行，去查
quality = 0.0   →  查过了，什么都没找到  ← 该澄清 / 该转人工
```
**它们看起来都是"没有质量"，但含义完全不同。**

**修法**：给 `quality` 加 `None` 这个值，第一次调用传 `None`，
分级函数见到 `None` 就直接返回"先让它走检索"。

**★ 教训**：
> **用 0 当"未知"的哨兵值是危险的。**
> 因为 0 往往是一个**合法的实际值**（检索质量真的是 0 分）。
> 该用 `None` 就用 `None`。

## 完整的判断顺序（写在这里备查）

```
① 无意义输入？        → 反问澄清（最多 2 次），不转人工
② 软风险（问流程）？   → 答流程 + 问全信息，不转人工
③ 硬风险（要数字）？   → 直接转人工，一个字不答
④ 简单问题？          → 不检索，模型直接答
⑤ 还没检索？          → 放行，去检索
⑥ 按检索质量：
     高质量           → 正常答
     中等 + 没重复      → 先答一次 + 请用户确认
     中等 + 重复提及    → 转人工
     没命中 + 没澄清过  → 澄清一次
     没命中 + 澄清过了  → 转人工
```

★ **顺序不能反**：软风险必须排在硬风险**前面**（"怎么报价"会被"报价"这个宽泛规则吃掉）；
无意义必须排最前；`quality is None` 必须排在质量分档前面。

## 修这一轮时又踩的四个坑（都记下来）

### 坑① `record_gap` 的参数个数不对，被 try 吞了

```python
learning.record_gap(tenant_id, q, channel, user_ref)   # 传了 4 个
def record_gap(tenant_id, question): ...               # 只收 2 个
→ TypeError → 被我自己的 try/except 静默吞掉 → 缺口一条没记上
```
★ **`except: pass` 是必要的（记缺口失败不该影响回答），但它也让 bug 隐身了。**
  修法不是去掉 try，而是**改完要独立验证结果**（我查了 open_gaps 才发现是空的）。

### 坑② `log_qa` 根本不写 `failure_reason`

「澄清过几次」这个计数查的是 `failure_reason='clarified'`，
但这个字段**只有事后 `decide()` 才写**，`log_qa` 不写。
→ 计数永远是 0 → **AI 无限反问**，用户被一直问"你想问什么"。

**修法**：把 `failure_reason` 加进 `log_qa` 的写入字段。

★ 教训：**判断依据所依赖的字段，必须在"判断发生之前"就已经落库。**
  不能依赖一个"最后才更新"的字段去做实时判断。

### 坑③ `decide()` 把已经记下的 `failure_reason` 覆盖成 NULL

```
log_qa 写入  failure_reason='clarified'
decide(outcome='sent')  ← 没传 reason → 覆盖成 NULL
→ 计数又变成 0
```

**修法**：`decide` 里用 `COALESCE(?, failure_reason)`。

★ 语义上的道理：
> `decide` 记的是**结果**（sent / edited / unanswered），
> 它**不该顺手抹掉"为什么失败"这个已经确定的事实**。
> 没传新原因，就保留原来的。

### 坑④ 无意义输入的"澄清到上限"被记成了缺知识

```
"工作台" 澄清 2 次 → 转人工 → 走进 no_hit 分支 → **记进待补充列表**
```
★ 但"工作台"这三个字**不是知识缺口**，记进去会污染待补充列表，
  让人以为"客户在问工作台的事，我们缺资料"。

**修法**：这类转人工的 `failure_reason` 标成 `should_escalate`（故意不答），
不是 `no_hit`（缺知识）。

**实测（修好之后）**：
```
"工作台"（无意义）  → 澄清 ×2 → 转人工，**不记缺口**
"团建费"（真缺知识）→ 澄清 ×1 → 转人工，**记缺口**
待补充列表：['团建费能不能报啊']   ← 只有真的
```
