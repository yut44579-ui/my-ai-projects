# 三档分级 + 渠道接入入口

> 用户的四条反馈：
> ① 实时同步用户 id 和聊天记录，随时知道用户在说什么，避免损失
> ② 模拟场景：「你是做什么的」这个 AI 是能回答上的
> ③ 分阶级：简单 / 中级（低风险）/ 高级（高风险）处理方式不一样
> ④ 接入微信或飞书的途径没有看到

---

## D78 ★★★ 「转人工」不该是一个动作，而应该是三档不同的策略

**用户的原话**：
> 「简单的问题 AI 不管里面知识库有没有存都可以回答；
>   中级的问题会先正常 AI 分析，并反复确认之后再转人工 ——
>   也就是用户重复提及一些模糊不清、但还是有点重要的；
>   高风险，用户直接提及高风险的问题，直接转。」

**★ 为什么这个设计是对的（我原来的两档是错的）**：

只做两档（能答 / 转人工）的系统，实际用起来是这样：
```
该答的答不了 → 用户觉得笨
不该答的乱答 → 客户觉得危险
```
而且**人的注意力是稀缺的**。把所有拿不准的都丢给人工，
人工队列会被淹掉，**真正紧急的那条反而没人看**。

三档的意义就是：**把人的注意力留给真正需要的那些。**

### 三档的具体定义

| 档 | 触发 | 处理 | 为什么 |
|---|---|---|---|
| **简单** | 寒暄、"你是做什么的"、道谢 | **不检索**，模型直接答 | 这类问题问的不是"公司的业务事实"，而是"你是什么"，答案是我们自己定义的 |
| **中级** | 检索命中但不够确定 | **先正常答一次 + 请用户确认**；只有**重复提及**才转人工 | 第一次问很可能是表达不清，答了他自己就明白了 |
| **高级** | 报价/合同/退款/投诉/法律/个人信息 | **直接转，一个字都不答**（连检索都不做） | 答错一次就是真金白银的损失或法律风险，"先答一下看看"这个念头本身就是错的 |

**★ 顺序不能反**：「你们公司多少钱」既有"公司"又有"多少钱"，
必须**先判高风险**再判简单。第一版就是这个顺序问题。

### 中级为什么是"重复提及才转"

```
第一次问  → 可能只是表达不清，答了他自己就明白了
换个说法又问 → ★ 说明第一次的回答**没解决问题**
              这时候再转，人工的注意力才没被浪费
```

### 「反复确认」不是客套

```
用户确认了       → 答对了，这一次不用转人工
用户说"不是这个" → 我们**立刻知道第一次理解错了**，
                   比让他换个说法再问一遍（然后我们才发现）早一整轮
```

所以中级问题发出去的时候，尾巴上带一句：
> （我理解你是想问这个。如果不是你的意思，你再说一句，我给你转人工。）

## D79 ★★★ 「你是做什么的」答不上来 —— 这类问题根本不该走检索

**现象**（用户在会话记录里看到的）：
知识库里明明有《公司简介》，但问「你是做什么的」AI 答不上来，
直接进了待补充列表。

**原因**：
```
问题的词：你 / 是 / 做 / 什么
资料内容：恒信精工成立于 2006 年，专注精密零部件制造二十年…
                        ↑ 一个字都不重合
→ 中文 2-gram 检索**必然命中不了**
```

**★ 所以这类问题不该走检索。**
它们问的不是"公司的业务事实"，而是"你是什么"——
**答案是我们自己定义好的，不需要查任何资料。**

**★★ 但必须上一道硬锁**：
```
只允许它介绍自己，**不许借机回答任何业务事实**。
否则就成了"模型想说什么就说什么"，违反第一条纪律（事实由程序算）。
```
系统提示里写死了：不要报价格、不要答政策、不要答流程、不要答数据。

**而且模型不可用时用固定话术**（`_self_intro_text()`），
不能让程序现编一句 —— 那同样是"事实由模型编"。

## D80 ★★ 2-gram 相似度：杰卡德不行，要用重叠系数

**现象**：「保修多久」和「你们那个保修多久啊」相似度只有 0.375，判不出重复。

**原因**：杰卡德 = 交集 / **并集**，会被长度差异严重惩罚。
```
「保修多久」         3 个 2-gram
「你们那个保修多久啊」 9 个 2-gram
杰卡德 = 3/9 = 0.33  → 判不出
重叠系数 = 3/3 = 1.0 → 判出来了
```

**★ 而"用户重复提及"的场景本来就是一次说得短、一次说得多**，
所以必须用对长度不敏感的口径。

**还有一个坑**：「我是说保修期」和「你们那个保修多久啊」
共享的只有「保修」一个 2-gram，被"我是说""那个""啊"这些语气词拉低了。

**修法**：算相似度之前**先去掉套话**（我是说 / 你们 / 那个 / 能不能 / 怎么 / 吗 / 呢…）。

修复后：14/14 分级判断正确，重复识别 3/3 正确。

## D81 ★★ 渠道接入的入口（用户说"没看到"）

**新增「渠道」标签页**，四个渠道各自的配置界面：

```
网页挂件   已接通     ← 直接在页面上给出嵌入代码
飞书       待配置     ← App ID / App Secret / Verification Token / Encrypt Key
企业微信   待配置     ← CorpID / AgentId / Secret / Token / AESKey / 内部员工名单
钉钉       待配置     ← 只有配置位（适配器还没实现，如实标注）
```

**★ 每个渠道都给三样东西**：
```
① 回调地址（完整的一条，复制粘贴就能填进平台后台）
   ★ 自己拼最容易拼错（路径、scheme、端口），直接给他最省事
② 接入步骤（可折叠，几步走完）
③ 配置字段（密钥类显示遮罩，原样提交表示"不改"）
```

**★ 侧栏给出选择建议**（这是客户最容易踩的坑）：
```
飞书    最省事 —— 支持长连接，不需要公网地址、不需要证书。私有化部署首选
企微    必须公网 —— 回调强制要求公网 HTTPS，不能用 IP:端口、不能自签证书
网页    零门槛 —— 不需要任何平台账号
```
> ★ **如果客户服务器在内网**：先推飞书。企微要么配公网入口，
> 要么用内网穿透 —— 后者要跟客户说清风险。
