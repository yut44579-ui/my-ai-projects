# 修正：旧产品名复发 + 一条永久护栏

## D63 ★★★ 口头约定靠不住，必须变成可执行的断言

**现象**：
```
用户明确说过「名字不要叫小笋供应链，叫 AI客服」
我改了当时提到的那一处
→ 过几轮，在新写的网页挂件里又用回了旧名字
```

**★ 这不是"忘了"，是方法错了**：
一次性修改和口头约定都是**靠记忆**的，
而记忆在长任务里必然失效。

**修法**：把它写成**每次跑测试都会执行的断言**（`scripts/smoke9.py`）：

```python
FORBIDDEN_NAMES = ["小笋", "小笋供应链"]
# 扫全项目所有会进仓库/上服务器的文件，命中就失败
```

**★ 这条的普遍意义**：
> **任何"不许出现 X"的要求，都应该变成一条会失败的测试。**
> 否则它一定会复发 —— 而且复发时你不一定看得到
> （这次是用户看出来的，不是我）。

## D64 护栏测试不能举报自己

**现象**：护栏第一次跑，报了 4 处"旧名字" —— 全在**它自己**里面
（检查器必须包含被禁字符串才能检查它们）。

**修法**：显式排除自己 + 支持 `ALLOW_FORBIDDEN_PATTERNS` 标记
（将来的检查器也用同一套）。

**★ 这类"自指"问题在任何扫描器里都会遇到**，
处理方式是**显式排除**，而不是把禁令放松 ——
放松了等于检查失效。

## D65 ★★ 测试脚本不该上生产服务器

**现象**：清掉服务器上的 `scripts/` 目录时，**把服务搞挂了**。

**原因**：`scripts/` 里除了测试脚本，还有 `serve.py` ——
**systemd 就是用它启动的**。整个目录删掉，服务当然起不来。

```
ExecStart=.../python scripts/serve.py --host 127.0.0.1 --port 8700
```

**★ 两条教训**：

**① 部署包里"哪些是运行必需的"要分清楚。**
测试脚本、文档、截图都不该上生产；启动脚本则是**必需的**。
不能按目录一刀切。

**② 删线上东西之前，先确认没有别的东西依赖它。**
我当时只想着"测试脚本不该在这"，没检查 `scripts/` 里还有什么。

**修法**：只回传 `serve.py`；并把"部署时排除测试脚本"写进部署脚本。

## D66 部署脚本的参数名要和函数签名对上

**现象**：两次部署"静默失败" —— 脚本报错，但我只看了尾部输出，
以为传上去了，实际上 `run(..., show=False)` 参数名不对直接抛异常，
**文件根本没传**。

**★ 教训**：部署之后必须**独立验证文件真的变了**
（`grep` 一下新代码在不在服务器上），
而不是相信"脚本没报错"。

**这次我是靠"部署了但行为没变"发现的** —— 如果行为碰巧看起来正常，
这个错会一直藏着。
