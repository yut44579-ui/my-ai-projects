# 里程碑 3 补充二：网页客服挂件 + 三个"过度拦截"的修复

> 网页挂件是**唯一不需要任何平台凭据就能真跑通**的渠道 ——
> 也是有网站的中小企业最主要的咨询入口。

---

## D52 网页渠道必须自建"发件箱 + 轮询"

**背景**：企微和飞书有"主动发消息 API"，AI 算完直接推给平台。
**网页没有** —— 浏览器那边只能自己来取。

**决策**：要发给浏览器的消息落进 `web_outbox`，浏览器按 seq 增量拉。

**★ 用自增 seq 而不是时间戳做游标**：
同一秒内产生的两条消息，用时间戳当游标会**漏掉一条**。
这类 bug 在生产上表现为"偶尔少一句话"，极难复现。

**为什么用轮询而不是 WebSocket**：
- 很多 SME 的网站挂在虚拟主机/共享空间上，**不支持长连接**
- 轮询走普通 HTTP，任何环境都能用
- 客服场景消息量很小（一个人几十秒一条），开销可忽略

代价是最多 1~2 秒延迟 —— 对客服场景完全可以接受。

## D53 ★★ 网页渠道的去重策略和企微**相反**

**决策**：网页渠道**不做去重**。

**理由**：
```
企微/飞书：平台会因超时**重发**同一条 → 必须去重，否则用户被答两遍
网页：     浏览器不会重发。用户连问两遍同一句，
           **那是他想再问一次**，不是系统重发
```

**★ 教训**：
> "去重"不是通用规则，是**对特定平台行为的应对**。
> 把某个平台的应对措施无脑套到所有平台，会引入新的错误
> —— 而且这种错误看起来像"功能不好用"，很难归因到去重上。

## D54 ★★ 转人工时必须给用户一个交代 —— 但要分清「谁在说话」

**背景**：早期我按 D6/D7 的判断"转人工就直接转，别说话"，
结果网页用户发完消息**面对一片寂静**，会以为系统坏了。

**★ 这其实和 D6/D7 不矛盾，区别在于「谁在说话」**：
```
✗ AI 说："我叫个同事帮你看下"      ← AI 在解释自己（禁止）
✗ AI 说："已转人工 · 财务 李姐"     ← 暴露岗位和姓名（禁止）
✓ 系统提示："—— 已转人工，稍等 ——"  ← 系统在陈述事实，不是 AI 在解释
```

**决策**：所有渠道在转人工时都发一条系统提示，措辞极短、无内部信息。

**★ 这个区分很重要**，因为它很容易被误读成"什么都不要说"，
而真相是"**不要让 AI 用它自己的口吻说话**"。

## D55 ★★★ 过度拦截：描述流程的职位词不是"泄漏身份"

**现象**（真跑发现的）：
```
问「请假怎么走流程」
→ 检索完全正常（质量 0.9）
→ 但出站检查把「主管」当成身份泄漏拦下 → 转人工
```

「请假需直属主管审批」是**正常的流程说明**，
和「已经转给财务部李姐处理」完全是两回事。

**★ 真正的区别在语境**：
```
✗ 泄漏：「已经转给财务部李姐处理」  ← 在告诉客户**谁在处理他这一单**
✓ 正常：「请假需直属主管审批」      ← 在描述**他要走的流程**
✓ 正常：「财务部应于5个工作日内付款」← 资料原文就是这么写的
```

**修法**：把一类规则拆成两类：
```
HANDOVER_LEAK（硬拦）：交接动词 + 部门/职位
    「已经转给财务部」「让法务处理」「我叫了售后」
ROLE_MENTION（仅提醒）：光秃秃的部门名/职位词
    「主管」「财务部」—— 可能只是资料原文的写法
```

**★ 这条的普遍意义（值得记住）**：
> **过度拦截和漏拦一样有害，而且更隐蔽。**
> 漏拦会出事故，有人投诉；过度拦截只会表现为"这个问题答不了"，
> 看起来像是知识库不够，**没人会想到是安全规则写得太宽**。

**修复后的实测**：这三条问题现在都能正常回答了。

## D56 ★ Excel 的 sheet 标记不能长得像 markdown

**现象**：Excel 第二个 sheet（请假流程）的内容**永远答不出来**。

**原因**（两个 bug 叠在一起）：
```
① 我用 "# {sheet名}" 当 sheet 标记
② 出站检查把 `^#{1,6}\s` 当成 markdown 残留 → 判定整条回答不合格 → 转人工
```

**修法**：sheet 标记改成 `【sheet名】`。

**★ 教训**：
> **自己生成的内容，不要长得像"需要被检查的东西"。**
> 出站检查是为了防模型的 markdown 泄漏，
> 但我自己往知识库里写了 markdown 记号，等于给自己埋了个雷。

## D57 ★ 表格数据行不可能是标题

**现象**：多 sheet 的 Excel，文档标题最终变成 `工龄 | 年假天数`，
出处显示成《工龄 | 年假天数》—— 比文件名还难懂。

**原因**：`_split_header` 取"正文里第一个像标题的行"，
而跳过 `【年假规则】` 之后，下一行就是表格的第一行数据。

**修法**：**带 `|` 的行是表格数据行，不可能是标题。**

**修复后**：标题正确回落到文件名《员工假期制度》。
