# 人工工作台：补上「完整会话记录」

## D73 ★★★ 只有一句话，客服没法回复

**用户原话**：
> 「人工这里可以看到具体用户上下文的聊天记录 这样才好回复与跟进 进度」

**他说得对。** 第一版人工工作台只显示：
```
当前这一句 + AI 查到的资料 + 为什么没答 + 检索质量
```

**这些东西回答不了客服真正需要知道的**：
```
· 他前面已经问过几遍了？          → 说明他有多急
· AI 刚才已经答了什么？            → 不能再答一遍一样的
· 他之前说过自己是谁、哪家公司？    → ★ 不用再问一遍
· 这个会话之前有没有被别人接手过？  → 别两个人同时回
```

**★ 最要紧的是第 3 条**：
> **让用户重复自己已经说过的话，是最伤的体验。**
> 而他一旦发现"你们客服不知道我刚才跟 AI 说了什么"，
> 就会立刻觉得"这个系统是拼起来的，不是一体的"。

**修法**：新增 `/api/handover/{id}/context`，把三条数据源拼成一条时间线。
```
qa_log          这个用户问过的每一句 + AI 的判断和回答
outbound_log    实际发出去的东西（AI 自动回的 / 客服回的）
handover_queue  人工处理历史（谁接手过、什么时候）
   ↓
一条按时间正序的会话记录
```

**实测效果**：
```
客户 10:23  最小起订量多少
AI   10:23  打样阶段 1 件起做，不限最低数量…〔出处：《交期与起订量》〕
客户 10:23  你们厂在哪儿
AI   10:23  江苏省苏州市工业园区星湖街 218 号，三号厂区。〔出处：《联系方式》〕
客户 10:26  能不能开专票
——          （这条 AI 没直接答，转人工了）  no_hit
```
头部还有一行摘要：**「问过 3 次 · 转人工 1 次 · 首次 10-09 10:23」**

## D74 ★★ 三张表的字段名不一致，差点让我写了个查空的接口

**现象**：`context` 接口第一次跑，时间线是空的。

**原因**：
```
qa_log          用 channel     + user_ref
outbound_log    用 platform    + user_id
handover_queue  用 platform    + user_id
```

**★ 教训**：
> **同一个概念在不同表里用了不同名字，是长期的隐患。**
> 它不会报错，只会**安静地查空** ——
> 而且你看到"没数据"的第一反应是"这个用户确实没问过"，
> 而不是"我列名写错了"。

这次先按准确列名写对，并在代码注释里标明这个不一致。
（统一列名是更大的重构，留作下次。）

## D75 ★ 同一句话在时间线上出现两遍

**现象**：AI 的回答在会话记录里出现了两次。

**原因**：AI 自动回答**同时**写进了 `qa_log.answer_text` 和 `outbound_log.content` ——
我从两个源各加了一遍。

**修法**：以 `qa_log` 为准，`outbound_log` 里内容重复的跳过
（只留客服人工发的那些）。

**★ 这类"两个地方记了同一件事"的问题会反复出现**：
只要有多个数据源描述同一个事件，拼时间线时就一定要去重。
**默认它们会重复，而不是默认它们不会。**

## D76 角标：一个需要人处理的队列，界面上不主动喊你就等于没有

**用户原话**：「工作台人工的那些在哪里，我看不到」。

**查下来**：标签一直在，所有屏幕宽度下都可见，队列里也有 8 条。

**★ 但没有任何东西告诉用户"这里有活等你干"**：
```
标签是灰的，没有数字，不显眼 —— 人在别的标签页就不会注意到
```

**修法**：
```
① 「人工」标签上加红色角标显示待处理条数（每 15 秒刷新，与当前所在标签无关）
② 模拟官网顶部加一条演示浮条，直接给控制台和人工页的入口
```

**★ 这条的普遍意义**：
> **一个需要人处理的队列，如果界面上不主动喊你，就等于没有。**
> 功能"存在"和用户"知道它存在"是两件事。

## D77 ★ 窄屏溢出：写死宽度 + 内联样式是重灾区

**现象**：手机上人工详情页横向溢出 49px。

**原因**：详情区是 `flex` + 右边 `width:270px` 写死的，
窄屏下中间那块被挤到溢出。

**★ 而且我第一版还用了**内联样式**：
```html
<div style="width:270px;flex:none">
```
内联样式**没法用媒体查询覆盖** —— 想改窄屏布局只能改 JS 字符串。
**修法**：改成 CSS 类，这样才能在 `@media` 里覆盖。

**教训**：
> **凡是要随屏幕变化的尺寸，就不能写成内联样式。**
> 这个坑在网页挂件（D61）已经踩过一次了。
