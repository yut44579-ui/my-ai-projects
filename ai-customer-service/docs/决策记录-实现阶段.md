# 开发过程中测出来的问题（里程碑 1）

> 这一节记的是**实现阶段被测试和截图抓出来的真实缺陷**，不是设计推演。
> 每一条都写了"为什么当时没发现"—— 那才是真正值得记的部分。

---

## D15 ★ 权限过滤把内外搞反了

**现象**：`【客户】住宿费一晚能报多少` → 质量 1.0，答得很好；
`【内部】住宿费能报多少` → 质量 0.0，0 命中。

```
★ 内部员工比外部客户看到的还少 —— 完全反了。
```

**原因**：`permission="internal"` 被当成"只搜 `internal` 文档"，
而演示资料全都标着 `external`，于是内部员工什么都搜不到。

**正确语义**：`permission` 表示**看的人有多大的可见范围**，不是"只搜这一种"：
```
external → 只能看标着 external 的
internal → 能看全部（含 external）
None     → 不过滤（后台审计用）
```

**为什么当时没发现**：最初的测试用例全是外部视角。
**只测一类用户，就永远发现不了"两类用户之间的相对关系错了"。**
→ 所以补的回归断言专门测"内部能看到的 ≥ 外部能看到的"。

## D16 ★ 转人工的原因不能靠事后反推

**现象**：截图里「我要投诉」被问了 4 次，排到了**待补充问题列表**前排。

**原因**：`_log()` 里用 `reason = "no_hit" if quality < 0.3 else "should_escalate"`
反推原因。而意图转人工（投诉/报价）的质量也是 0.0，
于是被误判成"缺知识"，进了待补充列表。

**正确做法**：**每个转人工的出口自己标注原因**，不靠事后猜。
四个出口分别是：
```
意图命中     → should_escalate（故意不答）
检索质量不够 → no_hit（找不到 → 缺知识）
模型说资料不足 → no_hit（资料里确实没有 → 缺知识）
出站检查拦下 → banned（安全问题）
```

**为什么要分清**：这两类的处理**完全不同**：
```
不会答   → 补知识库（管理员能做的事）
故意不答 → 判定规则在正常工作（不需要做任何事）
```
混在一起会把管理员带偏 ——
他以为该补资料，其实补不出一个"投诉答案"。

## D17 测试必须用独立的库

**现象**：服务在跑的时候跑冒烟测试，`PermissionError: 另一个程序正在使用此文件`。

**原因**：测试直接删 `data/kefu.db`，而服务正开着它。

**更重要的问题**：**测试在污染真实数据。**

**修法**：测试启动时设 `KEFU_DB` 环境变量指向临时目录。
★ 「测试不该碰开发/生产的库」是硬规矩，不是可选项。

## D18 测试要显式构造前置条件，不能依赖环境

**现象**：配好 API key 之后，一条老断言反而失败了：
`模型不可用时返回空而不是抛异常` —— 实际返回了 `〔无法回答〕`。

**原因**：那条断言隐含依赖"环境里没配 key"。配上之后，
它就变成了"对空资料调真模型"，而模型**正确地**回了 `〔无法回答〕`。

**教训**：测试要**自己构造**依赖的前置条件（临时清空 key 再测降级），
而不是依赖"这台机器恰好是什么样"。
★ 同一个测试在不同机器上结果不同，是最难查的一类问题。

**顺带**：这次"失败"其实是好消息 —— 说明约定标记 `〔无法回答〕` 真的生效了。

## D19 文档标题必须进索引

**现象**：搜「报价底线」（那是**文档标题**）命中不了那篇文档。

**原因**：分词只对正文做，标题没参与检索。

**为什么这很要紧**：标题是作者对内容最凝练的概括。
"XX的规定是什么""报销办法在哪个文件"这类问法**全靠标题**。
丢掉标题等于丢掉最强的检索信号。

**修法**：`tokenize(f"{title} {text}")`。

## D20 风格挖掘要比"去掉出处之后"的文本

**现象**：人工把
```
九点到六点，中午休一个小时。
〔出处：《员工手册》〕
```
改成
```
九点到六点，中午休一个小时。
```
系统记下的"改了什么"是：**「改短了；去掉了书名号引用」**。

**原因**：出站检查要求回答带出处，而人工发出去时通常**不带**
（他就在聊天窗口回一句，没人会把出处打给客户）。
于是每次人工改稿都被判成"改了"，风格示例库全是这种噪音。

**正确做法**：比较前先剥掉程序加的 `〔出处：…〕` 尾巴。
**实质没改的，不该进示例库。**

---

## D21 出处不能显示两遍

**现象**：界面上回答里带了 `〔出处：《费用报销管理办法》〕`，
下面又单独列了一行 `出处：《费用报销管理办法》`。

**做法**：正文里已经有了就不重复显示。
★ 正文里那句是**必须留**的 —— 企微/飞书都是纯文本，
界面上再漂亮，发出去也只剩纯文本，出处只能写在正文里。

---

## 从这一轮得到的三条通用教训

```
① 只测一类用户，发现不了"两类用户之间的相对关系错了"（D15）
② 靠事后反推原因，一定会推错（D16）
   —— 谁最清楚，就让谁说
③ 测试依赖环境、污染真实数据，是隐蔽性最高的一类问题（D17/D18）
```

★ 这三条都不是"AI 写错了代码"，而是**设计判断上的疏漏**，
而且**全都是靠真跑+看截图才暴露的**，读代码读不出来。
