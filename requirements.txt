# ★ 第一行那行 coding 声明**不许删**（这不是装饰，是修过的一个真 bug）：
#   pip 读 requirements 文件时走 auto_decode：有 BOM 就用 BOM，前两行有 PEP 263
#   coding 声明就用声明的编码，**两者都没有就退回系统 locale**。中文 Windows 的
#   locale 是 GBK，而本文件的注释是 UTF-8 → 解码炸在注释上，整个安装直接失败：
#       UnicodeDecodeError: 'gbk' codec can't decode byte 0xac in position 479
#   加了这行声明后 pip 明确按 UTF-8 读，任何 locale 都能装（已实测）。
#   等价做法是把文件存成 UTF-8 with BOM，但那会在文件里留不可见字节，不如声明清楚。

# 本清单冻结的是【项目声明的依赖】，不是【某台机器 venv 的快照】。
#
# 两者不是一回事：把 `pip freeze` 的全部输出倒进来，会把"这个项目需要什么"和
# "这台电脑恰好装过什么"混成一份无法解释的清单 —— 别人看不懂哪条能删、哪条不能删。
# 所以这里只写：
#   · 代码真的 import 的直接依赖（runtime direct）
#   · 加上少量必须钉住的关键传递依赖（显式写出的理由逐条见下）
# 其余传递依赖交给解析器自己拉，它们不是"项目选择了它们"，是"上面这些包选择了它们"。
#
# 版本来源：当前 `.venv` 实测（Python 3.11.15），**不升不降**，只如实记录已验证过的版本。
#
# 安装：
#     python -m venv .venv
#     .venv/Scripts/python.exe -m pip install -r requirements.txt      # Windows
#     .venv/bin/python -m pip install -r requirements.txt              # macOS / Linux
#
# 只有一个文件、不拆 requirements-dev.txt：现在只有一套环境（本机自用），
# 拆开只会立刻增加安装步骤、README 说明和维护关系。真出现运行/开发/CI 三套环境再说。
# ════════════════════════════════════════════════════════════════════════
